## 概览

实现目标（原则）
- 把所有敏感工作放在服务器端：密码哈希、JWT 签发与验证、cookie 设置/清除。  
- 使用 httpOnly、Secure（生产）cookie 存储 session token，客户端不能直接访问。  
- Serverless 友好：handler 快速返回；鉴权使用 JWT，数据库操作通过 `src/lib/db.ts` 的 serverless client。

## 环境变量
- `NEXTAUTH_SECRET` — 用于签发与验证 JWT session token（务必在生产中设置为高熵字符串）  
- `NODE_ENV` — 用于决定是否在 cookie 上添加 `Secure` 标志（production 时为 `production`）  
- `POSTGRES_URL` 或 `DATABASE_URL` — 数据库连接串（由 `src/lib/db.ts` 使用）

## src/lib/auth.ts — 库函数

用途：提供密码哈希/验证、会话 JWT 签发/验证、cookie 构造与解析等工具函数，供 API 路由使用。

导出函数（主要）
- `hashPassword(password: string): string` — 使用 bcryptjs 对明文密码进行哈希并返回哈希串。  
- `verifyPassword(password: string, hash: string): boolean` — 验证明文密码是否匹配哈希。  
- `signSession(payload: Record<string, any>): string` — 使用 `NEXTAUTH_SECRET` 签发 JWT，过期时间为 7 天（可在代码中调整）。  
- `verifySession(token: string): Record<string, any> | null` — 验证 JWT 并返回解码后的 payload，失败返回 null。  
- `makeSessionCookie(token: string, secure = false): string` — 生成 `Set-Cookie` 值（包含 HttpOnly, Max-Age, SameSite=Lax，生产环境会添加 Secure）。  
- `clearSessionCookie(): string` — 生成用于清除 cookie 的 `Set-Cookie` 值。  
- `readSessionFromHeader(cookieHeader: string | null): string | null` — 从请求 Cookie header 中解析 session token。

示例（伪代码）
```js
const token = signSession({ sub: userId, email });
res.headers.set("Set-Cookie", makeSessionCookie(token, process.env.NODE_ENV === "production"));
```

## POST /api/auth/register — 注册

路径：`src/app/api/auth/register/route.ts`  
方法：POST  
权限：公开  

请求体（JSON）
```json
{
  "email": "user@example.com",
  "password": "plaintext-password",
  "name": "Optional Name"
}
```

成功响应（201）
```json
{
  "ok": true,
  "user": {
    "id": "...",
    "email": "user@example.com",
    "name": "Optional Name",
    "role": "user",
    "account_tier": "free"
  }
}
```
同时，响应头会包含 `Set-Cookie`，设置 httpOnly session cookie（名称 `hrt_session`）。

错误响应
- 400 Missing email or password  
- 409 Email already in use  
- 500 Server error

行为说明
- 在写入 users 表前会检查 email 是否已存在（避免重复注册）。  
- 密码使用 bcrypt 哈希后保存到 `users.password_hash`。  
- 注册流程当前将 `email_verified` 设为 true（实际生产建议发送验证邮件并在验证后设置）。  

## POST /api/auth/login — 登录

路径：`src/app/api/auth/login/route.ts`  
方法：POST  
权限：公开  

请求体（JSON）
```json
{
  "email": "user@example.com",
  "password": "plaintext-password"
}
```

成功响应（200）
```json
{
  "ok": true,
  "user": {
    "id": "...",
    "email": "user@example.com",
    "name": "...",
    "role": "user"
  }
}
```
同时设置 httpOnly session cookie（`hrt_session`）。

错误响应
- 400 Missing email or password  
- 401 Invalid credentials  
- 500 Server error

行为说明
- 先在 `users` 表查找用户并取出 `password_hash`，使用 bcrypt 验证。验证成功后签发 JWT 并设置 cookie。

## POST /api/auth/logout — 登出

路径：`src/app/api/auth/logout/route.ts`  
方法：POST  
权限：已登录/公开（会清 cookie）  

响应（200）
```json
{ "ok": true }
```
同时在响应头中设置 `Set-Cookie` 清空 session cookie（Max-Age=0）。

## GET /api/auth/session — 查询当前会话

路径：`src/app/api/auth/session/route.ts`  
方法：GET  
权限：公开（根据 cookie 返回 user 或 null）  

请求：带 cookie 的请求（浏览器会自动附带 httpOnly cookie）  

成功响应（200）
```json
{
  "user": {
    "id": "...",
    "email": "user@example.com",
    "name": "...",
    "role": "user",
    "account_tier": "free"
  }
}
```
如果没有会话或 token 无效，则返回 `{ "user": null }`。

错误响应
- 500 Server error

行为说明
- 该路由从 `cookie` header 读取 `hrt_session`，验证 JWT，若有效则从数据库查询并返回用户基础信息（不返回 password_hash）。

## 安全与部署注意事项

- `NEXTAUTH_SECRET` 必须设置为高熵值并存放在 Vercel 环境变量中（或其他机密存储）。  
- Cookie 属性：
  - HttpOnly — 防止 JS 访问 cookie。  
  - SameSite=Lax — 减少 CSRF 风险（可根据需要调整）。  
  - Secure — 在 production (HTTPS) 环境下启用。  
- 对注册/登录接口实现速率限制与监控以防暴力攻击。可使用 edge 中间件或外部 rate-limit 服务。  
- 若支持 OAuth 登录（例如 Google One Tap），在 OAuth 成功后不要创建重复用户；应在 provider_id 上合并或关联账户。  
- 在 serverless 环境（Vercel）中，避免在每次请求创建新的数据库连接池。`src/lib/db.ts` 使用 `@neondatabase/serverless` 导出单个 `sql` 实例以便重用。  
- 日志与审计：对异常登录/注册事件记录日志并可上报至 Sentry。  
- Email verification：生产环境建议在注册后发送验证邮件并在确认后设置 `email_verified = true`（当前实现示例中直接设为 true）。

## 示例 curl 命令（用于本地测试）

- 注册：
```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"pass1234","name":"Alice"}' \
  -i
```

- 登录：
```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"pass1234"}' \
  -i
```

- 检查会话（示例使用 cookie）：
```bash
curl -X GET http://localhost:3000/api/auth/session \
  -H "Cookie: hrt_session=<your_token_here>" \
  -i
```
